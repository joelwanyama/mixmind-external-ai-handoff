# Phase 20 Regression Analysis: Canonical Master Beta Play/Seek Failure After Stale -
PlanSet Policy 
 
## Most likely root cause 
 
The regression is very likely caused by this implementation detail:  
 
```text 
cache.status() 
  -> isCurrent(current) 
    -> MasterPlanSet.build() 
``` 
 
That makes PlanSet status a **state -changing operation**. 
 
A status check must be read-only. If `status()` or `isCurrent()` can build, replace, rewrite, 
or normalize a PlanSet, then a normal Play command can mutate the tra nsport/plan 
state while: 
 
```text 
a canonical controller is still active,  
a stabilized seek state still exists,  
the UI loop is still running, 
the source ledger still references an old session,  
or the coordinator still holds an old controller/plan fingerpri nt. 
``` 
 
This can produce exactly the observed behavior:  

--- PAGE 2 ---
 
```text 
Play works initially. 
Seek works initially. 
Later Play moves the timer but produces no audio.  
Seek does not restore correct transport.  
Stop does not return to a clean restartable state.  
``` 
 
The second likely contributor is:  
 
```text 
Canonical beta start calls internal legacy Stop.  
``` 
 
If that internal legacy Stop performs full legacy side effects — resetting `currentTime`, 
`mixStartTime`, `trackStartTimes`, stopping the UI loop, stopping th e visualizer, or 
updating the Play button — it can silently destroy canonical transport state during a start 
or seek transaction. 
 
So the probable failure combination is:  
 
```text 
Side-effecting PlanSet status 
+ 
internal legacy Stop used inside canonical s tart 
+ 
non-terminal teardown events ignored by coordinator  

--- PAGE 3 ---
= 
main transport/UI state desynchronized from canonical audio graph  
```

# 1. Can `cache.status()` or `isCurrent()` rebuilding a PlanSet corrupt state while 
canonical controller is active? 
 
Yes. This is unsafe. 
 
A PlanSet status function must answer: 
 
```text 
Does a PlanSet exist? 
Is it sealed? 
Does its fingerprint match the current timeline/transitions/policy?  
``` 
 
It must not do any of the following:  
 
```text 
Build a new PlanSet. 
Replace the cached PlanSet. 
Mutate transitions. 
Mutate timeline metadata. 
Rewrite fingerprints. 

--- PAGE 4 ---
Reset transport state. 
Change currentTime. 
Change trackStartTimes. 
Invalidate an active controller. 
Stop or start UI loops. 
``` 
 
If `isCurrent()` calls `MasterPlanSet.bui ld()`, then a status check can create a new 
PlanSet object while the canonical controller is still using the previous one.  
 
That can cause these failures:  
 
## 1.1 Active controller references an old PlanSet  
 
The coordinator may hold: 
 
```js 
activeController.planFingerprint = oldFingerprint  
``` 
 
but `cache.status()` may replace the cached plan with:  
 
```js 
newFingerprint 
``` 
 
Now the controller and cache disagree.  

--- PAGE 5 ---
 
Possible consequence: 
 
```text 
Controller believes it owns one plan.  
Main UI reads timing from another plan.  
Play/Seek commands validate against another plan.  
Audio graph and UI state diverge.  
``` 
 
## 1.2 Plan rebuild may change timing metadata  
 
A rebuild may change: 
 
```text 
totalDuration 
mixStartTime 
trackStartTimes 
transition global starts 
effective transition durations 
``` 
 
If that happens while canonical beta is active or immediately before start, the UI 
scrubber can move using one timing model while the audio session uses another.  
 
That can produce: 
 

--- PAGE 6 ---
```text 
timer advances, 
but no audible source is connected correctly. 
``` 
 
## 1.3 Build may trigger cleanup internally  
 
If `MasterPlanSet.build()` internally stops playback, clears sources, or touches 
`AudioEngine`, then calling it from `status()` can perform a hidden Stop during  a Play or 
Seek command. 
 
That is especially dangerous in a queued transport architecture.  
 
## 1.4 Repeated status calls can repeatedly rebuild  
 
If the fingerprint is unstable — for example, if it accidentally includes transient state 
such as `currentTime`, `isPlaying`, UI selection, or temporary fallback flags — then 
`isCurrent()` may decide the plan is stale every time.  
 
That can cause: 
 
```text 
status -> rebuild -> status -> rebuild 
``` 
 
or: 
 
```text 

--- PAGE 7 ---
Play -> status rebuild -> controller start -> status rebuild -> transport corruption 
``` 
 
This matches the “worked once, then broke” pattern.

# 2. Should fingerprint comparison be pure and never call `build()`?  
 
Yes. 
 
Fingerprint comparison must be a **pure read -only comparison**. 
 
The correct separation is: 
 
```text 
Status: 
  read current inputs 
  compute current fingerprint  
  compare with stored sealed fingerprint  
  return MISSING / STALE / CURRENT 
 
Build: 
  explicit command 
  only when stopped 
  creates/seals a PlanSet 
  writes cache 

--- PAGE 8 ---
``` 
 
Status must never build. 
 
Recommended rule: 
 
```text 
MasterPlanSet.build() may only be called by:  
  explicit Build Initial PlanSet command  
  explicit Rebuild Master Plans command  
 
MasterPlanSet.build() must never be called by:  
  cache.status() 
  isCurrent() 
  Play validation 
  Seek validation 
  UI rendering 
  scrubber updates 
  controller event callbacks  
```

# 3. Should stale detection happen only while stopped, or can it run during canonical 
playback? 
 
## Detection may be pure anytime  

--- PAGE 9 ---
 
Stale detection itself can run at any time if it is pure:  
 
```text 
compute current fingerprint 
compare stored fingerprint 
return status 
``` 
 
That is safe. 
 
## Enforcement must not mutate during active playback  
 
But stale enforcement must not rebuild, replace, or invalidate the a ctive canonical 
session from inside a status call.  
 
Safe policy: 
 
```text 
Before Play: 
  pure status check 
  if missing/stale: refuse or explicit build command  
 
Before Seek: 
  pure status check only if needed  
  do not rebuild during seek 
 

--- PAGE 10 ---
During playback: 
  do not call status repeatedly from UI loops  
  do not rebuild while canonical controller is active  
  if timeline edits make the plan stale, stop safely at a transport boundary  
``` 
 
If the plan becomes stale during playback because the user edited the time line, the 
safest behavior is: 
 
```text 
Mark plan stale. 
Stop canonical playback safely with visible message.  
Require rebuild before next Play. 
``` 
 
Do not silently rebuild under the active controller.

# 5. Can `teardown(false, 'START')` leave state inconsistent?  
 
Yes. 
 
`teardown(false, 'START')` is dangerous if it combines:  
 
```text 
non-terminal canonical teardown  
``` 
 
with: 
 
```text 
internal legacy Stop side effects 
``` 
 
The main coordinator is designed to ignore  non-terminal beta events. That is correct for 
seek transactions. But if the same non -terminal teardown path calls internal legacy 
Stop, and that legacy Stop resets:  
 
```text 
AudioEngine.currentTime 
AudioEngine.mixStartTime 
AudioEngine.trackStartTimes 

--- PAGE 19 ---
AudioEngine.isPlaying 
UI update loop 
visualizer 
Play button 
``` 
 
then the coordinator may believe canonical beta is starting or still owns transport, while 
the underlying AudioEngine display state has been reset to legacy stopped state.  
 
This can produce: 
 
```text 
UI timer moves because a later start sets isPlaying true,  
but session bus/source graph is not correctly connected,  
or controller ownership was cleared by legacy Stop,  
or timing metadata was reset underneath the canonical controller.  
``` 
 
So yes: 
 
> `teardown(false, 'START')` can leave main transport/UI/controller state inconsistent if 
internal legacy Stop performs full transport resets.  
 
The fix is to separate: 
 
```text 
canonical session teardown 
``` 

--- PAGE 20 ---
 
from: 
 
```text 
legacy full stop 
``` 
 
and from: 
 
```text 
legacy source cleanup only 
```

# 6. Should canonical beta start have a separate `RESET_FOR_START` transaction?  
 
Yes. 
 
Start and seek have different invariants.  
 
## Seek teardown 
 
Seek teardown must be non-terminal and must preserve canonical transport ownership: 
 
```text 
SEEKING 

--- PAGE 21 ---
  -> TEARDOWN 
  -> STABILIZING 
  -> STABILIZED 
``` 
 
It must not emit: 
 
```text 
terminal STOPPED 
``` 
 
It must not clear main coordinator ownership unless the seek fatally fails.  
 
## Start reset 
 
Start reset must prepare a fresh canonical session. It should be its own transaction:  
 
```text 
START_REQUESTED 
  -> PLAN_STATUS_PURE 
  -> START_RESET 
  -> START_CONNECT 
  -> START_RUNNING 
``` 
 
or for stabilized resume: 
 

--- PAGE 22 ---
```text 
START_REQUESTED 
  -> PLAN_STATUS_PURE 
  -> STABILIZED_START_RESET 
  -> STABILIZED_CONNECT 
  -> STABILIZED_RUNNING 
``` 
 
`RESET_FOR_START` should: 
 
```text 
Stop previous canonical session safely. 
Clear source ledger. 
Disconnect old session bus. 
Increment session token. 
Set activeController to the new session. 
Set timing metadata from the sealed PlanSet.  
Start UI/visualizer exactly once.  
``` 
 
It should not use the same semantics as seek teardown.

# 7. How PlanSet rebuild should interact with transport state  
 
PlanSet rebuild is a destructive operation for canonical playback state.  

--- PAGE 23 ---
 
It must not occur while canonical playback is active.  
 
## Recommended rebuild sequence  
 
```text 
User clicks Rebuild Master Plans  
  -> if canonical active: stop canonical safely first  
  -> set transport state to STOPPED_REBUILDING  
  -> invalidate active controller  
  -> increment planEpoch 
  -> build new Master PlanSet  
  -> seal new PlanSet 
  -> store new fingerprint 
  -> reset currentTime to 0 
  -> clear stabilized target 
  -> clear trackStartTimes/mixStartTime and replace from new plan  
  -> clear source ledger 
  -> stop UI loop 
  -> stop visualizer 
  -> set state STOPPED_PLAN_READY  
``` 
 
## Interaction details 
 
### currentTime 
 

--- PAGE 24 ---
Recommended: 
 
```text 
Rebuild resets currentTime to 0. 
``` 
 
Reason: 
 
The old global position may not be valid in the new PlanSet if transition durations, track 
order, offsets, or fallback recipes changed. 
 
If you later want to preserve position, you must add a explicit mapping step:  
 
```text 
old global time -> new owning track -> new local offset 
``` 
 
Do not add that in the initial repair. 
 
### mixStartTime 
 
Replace from the new sealed PlanSet.  
 
Do not allow legacy Stop or rebuild to leave a stale legacy `mixStartTime` visible while 
canonical beta is next started.  
 
### trackStartTimes 
 

--- PAGE 25 ---
Replace from the new sealed PlanSet.  
 
The scrubber must use canonical trackStartTimes when canonical beta is active.  
 
### activeController 
 
Rebuild must clear: 
 
```text 
activeController 
activeControllerSessionId 
canonicalSubState 
stabilizedTarget 
``` 
 
or mark them invalid. 
 
### session token 
 
Rebuild must increment: 
 
```text 
planEpoch 
controllerSessionToken 
``` 
 
Any old controller events must be ignored.  

--- PAGE 26 ---
 
### UI update loop 
 
Rebuild while stopped should leave UI loop stopped.  
 
If rebuild is triggered while playing, playback must first stop and UI loop must stop.  
 
### visualizer 
 
Rebuild should not start the visualizer. 
 
If playback was active, stop visualizer during the safe stop before rebuild.  
 
### source ledger 
 
Rebuild must require: 
 
```text 
source ledger empty 
``` 
 
If not empty, stop and clear before completing rebuild.

# 9. Pure PlanSet fingerprint/status design  
 
The PlanSet cache should expose pure status  functions. 
 
## 9.1 Fingerprint inputs 
 
The fingerprint should include only plan -building inputs, not transient playback state.  
 
Include: 
 

--- PAGE 34 ---
```text 
plan schema version 
planner version 
master fallback policy version 
canonical Master-only execution policy version 
timeline track order 
track IDs 
track replacement/version tokens  
track duration/trim/offset versions 
master analysis versions 
transition types 
transition requested durations 
manual transition override flags  
force-master lock provenance, if part of plan  input 
``` 
 
Do not include: 
 
```text 
currentTime 
isPlaying 
scrubber position 
UI selection 
visualizer state 
activeController 
session token 
legacy playback mode 

--- PAGE 35 ---
temporary refusal state 
``` 
 
--- 
 
## 9.2 Pure fingerprint function  
 
```js 
function computeMasterPlanSetFingerprint(inputs) {  
  const parts = [ 
    inputs.schemaVersion, 
    inputs.plannerVersion, 
    inputs.fallbackPolicyVersion, 
    inputs.masterOnlyPolicyVersion, 
 
    inputs.timelineTrackOrder.join("|"), 
 
    ...inputs.tracks.map(track => [  
      track.id, 
      track.versionToken, 
      track.durationRoundedMs, 
      track.offsetRoundedMs, 
      track.masterAnalysisVersion 
    ].join(":")), 
 
    ...inputs.transitions.map(transition => [  
      transition.id, 

--- PAGE 36 ---
      transition.type, 
      transition.requestedDurationRoundedMs,  
      transition.manual ? "manual" : "auto",  
      transition.forceMasterLockKind || "none"  
    ].join(":")) 
  ]; 
 
  return deterministicHash(parts.join("||"));  
} 
``` 
 
This function must not: 
 
```text 
call MasterPlanSet.build() 
write to cache 
mutate inputs 
reset transport 
touch AudioEngine 
```

## 9.3 Pure status function 
 
```js 
function getMasterPlanSetStatus() {

  const currentInputs = getCurrentMasterPlanInputs();  
  const currentFingerprint = compute MasterPlanSetFingerprint(currentInputs);
``` 

# 12. Unsafe design decisions to avoid  
 
## 12.1 Status that builds 
 
Unsafe: 
 
```text 
cache.status() -> MasterPlanSet.build() 
``` 
 
Safe: 
 
```text 
cache.status() -> pure fingerprint comparison 
``` 

--- PAGE 60 ---
 
--- 
 
## 12.2 Rebuilding during active playback  
 
Unsafe: 
 
```text 
Canonical controller active 
  -> status detects stale 
  -> rebuild replaces plan under controller  
``` 
 
Safe: 
 
```text 
Detect stale purely. 
Stop or refuse. 
Rebuild only at stopped transport boundary. 
``` 
 
--- 
 
## 12.3 Internal legacy Stop resetting canonical state  
 
Unsafe: 
 

--- PAGE 61 ---
```text 
Canonical start calls legacy full Stop.  
Legacy full Stop resets currentTime, trackStartTimes, UI, visualizer.  
``` 
 
Safe: 
 
```text 
Canonical start calls legacy cleanup-only. 
Coordinator owns UI/time synchronization.  
``` 
 
--- 
 
## 12.4 Reusing seek teardown for start  
 
Unsafe: 
 
```text 
teardown(false, 'START') 
``` 
 
with the same semantics as seek.  
 
Safe: 
 
```text 

--- PAGE 62 ---
RESET_FOR_START for start. 
SEEK_TRANSACTION for seek.  
``` 
 
--- 
 
## 12.5 Letting non-terminal events hide full legacy resets  
 
Unsafe: 
 
```text 
Non-terminal canonical event ignored by coordinator,  
but internal legacy Stop already reset transport state.  
``` 
 
Safe: 
 
```text 
Non-terminal events must not perform full transport resets.  
Full resets must be explicit and terminal.  
```

# Bottom line 
 

--- PAGE 63 ---
The likely regression is not primarily a Web Audio bug. It is a command -boundary and 
state-machine bug introduced by Phase 20.  
 
The unsafe pattern is: 
 
```text 
Play 
  -> cache.status() 
    -> isCurrent() 
      -> MasterPlanSet.build() 
        -> possible PlanSet replacement / side effects  
          -> canonical start 
            -> internal legacy Stop resets UI/time  
              -> transport state and audio graph diverge  
``` 
 
The safe repair is: 
 
```text 
Make PlanSet status pure. 
Make fingerprint comparison side-effect-free. 
Make build/rebuild explicit stopped commands.  
Split legacy full Stop from legacy cleanup -only. 
Give canonical start its own RESET_FOR_START transaction. 
Keep seek teardown non-terminal and transport-preserving. 
Stop must always force a clean terminal state.  
Rebuild must reset canonical transport to a known stopped state.  

--- PAGE 64 ---
``` 
 
With those changes, Phase 20 can enforce stale -plan refusal without corrupting the 
already validated Canonical Master Beta playback and Abort -and-Stabilize seek 
behavior.
